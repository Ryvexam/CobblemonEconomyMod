# Cobblemon 1.7/1.8 compatibility specification

## Goal

Prevent the Pokédex capture crash introduced by Cobblemon 1.8 while keeping the
capture/discovery reward flow compatible with both Cobblemon 1.7 and 1.8.

## Confirmed API difference

- Cobblemon 1.7 exposes `PokedexEntryProgress.CAUGHT`.
- Cobblemon 1.8.1 exposes `PokedexEntryProgress.OWNED` instead.
- `PokedexDataChangedEvent` PRE/POST still exposes `getKnowledge()` and the
  existing event flow remains usable.

## Design

- Build the mod against Modrinth Maven coordinate
  `maven.modrinth:MdwFAVRL:gBW3vLC7` (Cobblemon Fabric `1.8.1` for 1.21.1),
  Fabric Loader 0.17.2, and Fabric API
  0.116.6+1.21.1.
- Replace direct enum constant references with a small helper that accepts the
  enum as `Enum<?>` and recognizes the logical names `CAUGHT` and `OWNED`.
- Use the helper for PRE, POST, and first-species checks so all discovery paths
  share the same compatibility rule.
- Keep `fabric.mod.json` compatible with Cobblemon `>=1.7.1`; runtime API use
  must not directly link either removed/added enum constant.
- Add unit tests for `CAUGHT`, `OWNED`, and non-owned statuses.
- Verify through the standalone Minecraft agent MCP: inspect, build, test, read
  logs, and list artifacts.

## Non-goals

- No unrelated Cobblemon 1.8 feature migration.
- No redesign of capture rewards, persistence, or event de-duplication.
- No claim that a dedicated server test passes if required runtime mods are
  unavailable or incompatible in the local environment.
