# Cobblemon 1.7/1.8 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the capture Pokédex listener run with both Cobblemon 1.7 and 1.8 while building and testing the mod against Cobblemon 1.8.1.

**Architecture:** A dependency-free compatibility helper translates the logical Pokédex progression names into the mod's owned/caught predicate. `CobblemonListeners` remains the event owner; only its direct enum comparisons change. The build target moves to 1.8.1 while Fabric metadata keeps the runtime lower bound at 1.7.1.

**Tech Stack:** Java 21, Fabric Loom, Cobblemon 1.8.1, JUnit 5, SQLite, standalone Minecraft-agent MCP over stdio.

**Spec:** `docs/superpowers/specs/2026-09-19-cobblemon-1.8-compatibility-spec.md`

## Global Constraints

- Support both logical progression names: `CAUGHT` and `OWNED`.
- Build target: Modrinth Maven coordinate `maven.modrinth:MdwFAVRL:gBW3vLC7` (Cobblemon Fabric 1.8.1 for 1.21.1), Fabric Loader `0.17.2`, Fabric API `0.116.6+1.21.1`.
- Runtime metadata lower bound remains Cobblemon `>=1.7.1`.
- Do not directly reference `PokedexEntryProgress.CAUGHT` or `.OWNED` in production code.
- Verify through MCP and classify unavailable runtime dependencies honestly.

## Review Focus

- Enum linkage: loading the listener must not throw `NoSuchFieldError` on either version.
- Discovery PRE/POST: first species detection must work for both status names.
- Existing knowledge: `SEEN`/`ENCOUNTERED`/`UNREGISTERED` must not count as owned.
- Build dependency coherence: the resolved classpath must contain Cobblemon 1.8.1 and the minimum Fabric versions.
- Runtime diagnostics: MCP test output must distinguish a fixed mod from missing/incompatible external mods.
